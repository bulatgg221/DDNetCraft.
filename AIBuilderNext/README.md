# AI Builder Next 1.0.0-alpha.1

Новая реализация для Minecraft Java 1.21.1, Fabric Loader 0.16.14,
Fabric API 0.115.6+1.21.1 и Java 21. Исходники прототипа 0.10.1 находятся
в соседней папке AIBuilder и не изменены. Это alpha для проверки в игре.

## Установка и использование

1. Скачайте `aibuilder-fabric-1.0.0-alpha.1.jar` из артефакта GitHub Actions
   `aibuilder-next-1.21.1`. Файл с `-sources` предназначен для разработчиков.
2. В папке `mods` оставьте только одну версию AI Builder и Fabric API для 1.21.1.
3. Откройте одиночный творческий мир. F8: провайдер, точный ID модели, API-ключ.
   Polza: например `openai/gpt-4.1`; OpenAI: `gpt-4.1`. Доступность зависит от API.
4. F7: описание до 16000 символов, режим, желаемый размер и детализация.
   Генерация вызывает платный API один раз. Локальный импорт PNG не вызывает API.
5. После генерации нажмите «Предпросмотр»: схема отдельных слоёв, размеры,
   число блоков и операций, материалы, координаты и предупреждения.
6. «Подтвердить строительство» запускает проверку территории и размещение.
   `/ai cancel` останавливает работу, `/ai undo` восстанавливает изменённые блоки,
   `/ai redo` повторяет успешный откат при отсутствии конфликтов.

F7 сохраняет черновик при закрытии. Изменённый текст отчёта в предпросмотре
не изменяет план. Цвета схемы условные, это не 3D-рендер и не просмотр текстур.

## Изображения

Поместите PNG в `config/aibuilder-next/import.png`, выберите F7 → «Из import.png».
Ограничения: 8 МБ, 4096×4096 исходных пикселей, результат 8..64.
Изображение вписывается в квадрат с сохранением пропорций, прозрачность пропускается,
цвет выбирается по расстоянию в линейном RGB среди 16 оттенков бетона.
Цветовые образцы приблизительные и не учитывают resource packs.
Для 48/64 пикселей по высоте увеличьте допустимую высоту в F8.
Генерация изображений через стороннюю image API и визуальная оценка LLM не реализованы.

## Команды

`/ai help`, `/ai version`, `/ai status`, `/ai build <описание>`, `/ai confirm`,
`/ai cancel`, `/ai undo`, `/ai redo`, `/ai selftest`, `/ai config reload`,
`/ai history`, `/ai saveplan <имя>`, `/ai loadplan <имя>`.

Сохранять можно готовый план до подтверждения. Имена проектов: латиница, цифры,
`_` и `-`. Файлы содержат описание, дату, модель, исходный план и итоговые воксели;
API-ключей в них нет. При загрузке план снова компилируется и проверяется.

## Безопасность и лимиты

По умолчанию: 400 операций, 30000 уникальных блоков, 300 изменений за тик,
локальные X/Z ±48, Y ±32. Абсолютные пределы: 512 операций, 100000 блоков,
X/Z/Y ±128, 1000 изменений за тик. Дополнительный лимит времени очереди — 8 мс.
Проверка территории тоже идёт порциями. На перекрытия операций есть отдельный бюджет.

Перед строительством фиксируется состояние каждой затронутой клетки; при изменениях
между проверкой и размещением работа останавливается. Undo/redo сравнивают состояния
и не затирают обнаруженные чужие изменения. История одна, только в текущей сессии.
Отмена не выполняет автоматический откат: используйте `/ai undo`.
Переход в другое измерение или выход останавливает работу; поздний ответ API игнорируется.
История не сохраняется после закрытия мира.

Существующие block entities (сундуки и т. п.) защищены: план, затрагивающий их,
не строится. Поэтому содержимое контейнеров не уничтожается и NBT не требуется
восстанавливать. Новые кровати проверяются как согласованные пары.
Вода допускается только внутри замкнутого объёма со стенами и дном из полных блоков
плана и размещается последней. Генерация команд, NBT, файловых путей и URL запрещена.
Физика соседей не запускается при размещении: некоторые соединения заборов/панелей
могут требовать обновления в игре. Это ограничение защищает область от каскадных изменений.

## API и ключи

Конечные адреса фиксированы: `https://polza.ai/api/v1` и `https://api.openai.com/v1`.
Запросы выполняются вне игрового потока. Ответ ограничен 2 МБ и 180 секундами.
Поддерживаются сообщения об HTTP 400/401/402/403/404/429, пустом ответе,
обрезке по finish_reason и ошибках локального плана. При 429 учитывается Retry-After.
Кнопка проверки использует GET /models; она не доказывает возможность генерации
конкретной моделью. Автоматические платные повторы выключены. Новый запрос запускается
игроком явно; повреждённый план не заменяется готовой схемой.

Ключи хранятся в памяти либо читаются из POLZA_API_KEY / OPENAI_API_KEY.
На Windows можно включить DPAPI CurrentUser. Зашифрованный файл читается только
в контексте того же пользователя Windows. Работа DPAPI требует проверки на Windows.
В других ОС постоянного сохранения ключа нет. Подписка ChatGPT не заменяет API-баланс.

## Архитектура и качество

Модель возвращает в одном ответе спецификацию, компоненты, связи, разделы и операции.
В основном режиме нет `buildHouse`, `buildCastle`, готовых планировок или подмены
сложного запроса уменьшенной коробкой. Разделы выполняются в порядке зависимостей,
но пока весь проект должен помещаться в один ответ и общий лимит.

Проверяются: JSON/дубликаты ключей/переполнение, реальные ID и свойства блоков,
границы компонентов, пары дверей/кроватей, проходы с двумя свободными клетками,
связь основных помещений с входом, крупные неподдержанные части, положение крыши,
наличие воды в бассейне, явно указанное число башен (простые русские формулировки).
Проверка проходимости консервативна: путь требует явно запланированного воздуха.
Эвристики разнообразия и цветового состава не гарантируют красоту или сходство портрета.
Смысловое распознавание всех признаков запроса и точная геометрия коллизий игрока
для каждого вида неполных блоков ещё не реализованы.

## Сборка и проверки

Установите Java 21 и Gradle 8.8. Из корня репозитория:

```
gradle -p AIBuilderNext build --no-daemon
gradle -p AIBuilderNext runSmoke --no-daemon
```

`build` запускает JUnit и создаёт remapped Fabric JAR.
`runSmoke` запускает реальный Fabric/Minecraft runtime, проверяет палитру,
свойства, геометрические примитивы, длинные планы и pixel rows, затем выходит
до создания игрового мира. Платный API не используется.

Не проверены: F7/F8 в графическом клиенте, реальное строительство и физика мира,
платные запросы Polza/OpenAI, качество трёх требуемых архитектур и портрета,
Windows DPAPI, LabyMod. Для этого нужны запущенный клиент и доступ к выбранному API.
Alpha нельзя считать выполнением всех критериев готовности исходного ТЗ.

P2 остаётся: многошаговое платное проектирование больших проектов с отдельным
подтверждением стоимости, полноценный 3D-рендер, image-generation API,
визуальная оценка и улучшение качества, полноценная поддержка серверов.
